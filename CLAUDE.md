## What this is

A portfolio analytics project on the Kaggle "Financial Transactions Dataset" (about 13.3M card transactions plus 2k users, 6k cards, MCC codes and partial fraud labels). It is laid out as six stage notebooks following the same lifecycle as the NHS-Trust-Financial-Analytics repo. See [README.md](README.md) for the research question and the methodological corrections made to the earlier notebook, which was removed and is only in git history (commit `d9d7bcb`).

## Data flow (read before changing the pipeline)

- **Source:** OneDrive `TeslimDataLakes/financial_transactions_dataset_analytics_kaggle/`, read only through `onedrive_loader.load()` (read-only Graph API; credentials in the connector repo's `.env`). **Don't download from Kaggle.** Only stage 2 (`python/ingestion.py`) contacts OneDrive.
- **Medallion cache** (`data/`, gitignored):
  - bronze = every column as text, with the JSON dictionaries reshaped to two columns
  - silver = typed via `python/cleaning.py`
  - gold = `sql/gold/*.sql` plus pandas model outputs written with `warehouse.write_gold`
- **DuckDB (`python/warehouse.py`)** exposes each Parquet file as a view named `silver_<table>` / `gold_<table>`. `refresh_views` re-registers them after every gold write. SQL files are plain SELECTs, and `sql_text()` strips the trailing `;` so they can be wrapped in `COPY (...)`.
- **Gold build order matters:** `customer_monthly_variance.sql` joins `gold_monthly_spend` for its complete-month calendar.
- **Stage 5** reconciles gold totals back to silver and refuses to export if they differ. Extracts go to `outputs/powerbi/`.

## Invariants that are easy to break

- **No leakage in forecast features:** every window in `monthly_spend.sql` ends at `1 PRECEDING` and is NULL until full. `mom_growth_pct` and `yoy_growth_pct` are descriptive only and must stay out of `forecasting.FEATURES`.
- **Variance budget comes from prior months only** (trailing three, all three required). Favourable means actual ≥ budget, from the portfolio-volume perspective.
- **"Net spend", not revenue:** amounts include negative refunds. The data has no issuer revenue.
- **Fraud rates are always fraud / labelled transactions,** because the labels cover only part of the data.
- **Customer aggregates come straight from transactions.** Never join monthly rows before summing.
- **RFM recency uses fixed day bands** (`segmentation.RECENCY_BANDS`), not quintiles. 91% of customers have recency = 1 day, so quintiles would split ties arbitrarily.
- **Stage 2 downloads `transactions_data.csv` with a resumable chunked download** (`ingestion._download_resumable`). A single-GET `onedrive_loader.load()` was reset mid-transfer on the 1.26 GB file. This relies on the connector's private `_get_token` / `_onedrive_path`. `ingest_all()` reuses cached bronze tables unless `refresh=True`.
- `card_number` and `cvv` are dropped at silver and must never reach gold or the exports.
- The stage 6 executive summary is generated with f-strings from the gold tables. Keep findings computed, not hard-coded.
